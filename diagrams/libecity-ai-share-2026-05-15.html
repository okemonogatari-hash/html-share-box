1 Claude Code と Codex、結局どう違うの？

シェア会で出てきた直球の質問

Codex だけ使ってる。Claude Code まで使う必要ある？ — 参加者から

2026年の今、この2つは「AIに頼んでパソコンを動かしてもらう」系のツールとしてツートップ。やってることは結局同じ（ファイル操作・コード生成・実行）なので、片方を使いこなせばもう片方への乗り換えも普通にできる、というのが会全体の共通認識でした。

🧡 Claude Code

  • デスクトップアプリ版が出て入りやすくなった
  • 「許可しますか？」を1個ずつ押す丁寧モード
  • PowerPoint生成はちょっと苦手
  • 記憶を育てると「育成ゲーム」感が強い

💜 Codex

  • プロプラン($20)の使える枠が体感3倍くらい広い
  • 画像生成を中で完結できる（ChatGPT等に投げ直さなくていい）
  • ブラウザ操作・PC操作の自動化が大幅進化
  • 初見で「秒数表示？」と挫折する人もいるUI
会で出たおけもんの推し： 「今ならまず Codex でいい」。
理由は枠の広さと、ブログ書きながらブログ用の画像までその文脈のまま作れる便利さ。Claude Code を否定する話ではなく、両方触ったうえでの個人的おすすめという温度感。

3 Codexがブラウザ・PCを動かす実演（LINE送信デモ）

会の途中で Codex に裏で仕事させて、終盤に答え合わせ

今回のCodexアップデートで、ブラウザ操作と「PCのアプリ画面そのものを読み取って操作する」自動化が、ヤバいぐらい人間並みにできるようになっています。会では、おけもんが事前に Codex に 「KIDさんに LINE で『やっほー』って送って」 と指示済み。

👀 Codex が PC版 LINE を起動する
🔍 KIDさんとの個別トークを探しに行く
⚠️ 間違えて公式アカウントを開いてしまう
↩️ 自分で気付いて切り替えて、本人と同じ操作感でメッセージ送信
📲 実際にKIDさんのLINEに「やっほー」が届いて、会の場が沸く

日常での使い方例（おけもん）

サブスクの解約：「Xサーバーから更新案内メール来たから、見に行って解約まで進めといて」と Codex に投げるだけ。あとは自動で管理画面を開いて解約処理まで完了。

補足：LINEはなぜ "画面操作" 方式なの？

LINEの個別チャットには公式の API（外から命令を受け付ける窓口） や MCP（AIから繋ぐ専用のパイプ） が存在しない。だから AI に LINE を触らせたい場合は「パソコン画面そのものを読み取って操作する」やり方になる。Slack のような窓口が公開されているツールは、画面操作よりそっち経由のほうが軽くて速い。

📌 ここから読み取れること：
Codex / Claude in Chrome みたいな「画面そのものを動かしてくれるAI」が出てきたことで、API がないアプリでも自動化できる時代に入った。FC2にアップする、LINE送る、サブスク解約する、みたいな細かい操作を全部肩代わりさせられる。

人は「何を」教わるかより

5 その他の生の声・具体的な使い方

note運用代行を AI に "覚えさせる" 試み

複数クライアントの note 代行をしている参加者の話：Claude Code（デスクトップアプリ版）に、クライアント別にターゲット・トーン・NGテーマを覚えさせることで、月次の打ち合わせ → 文字起こし → 執筆 → 投稿 → 報告までを順番に自動化中。「言ってないことまで盛り込んでくれた」と感動するくらいに育ってきている。

PowerPoint問題（みんなここで詰まりがち）

Claude Code は PowerPoint をきれいに作るのが意外と苦手。実用的なフロー：

  • ① Claude Code に PowerPoint用の情報をきれいにまとめさせる（構成・文言・参考画像のリストアップ）
  • ② 出てきた素材を Claude Design / Manus / 通常のClaude（チャット版）など、スライド生成が得意なツールに渡して仕上げる

「全部Claude Codeで完結させなきゃ」と思わなくていい、という気付きの話。

LINEスタンプ販売を ChatGPT × Codex で量産

参加者の事例：ChatGPTで卓球女子のイラスト生成 → LINEスタンプ規定サイズに自動加工 → Codexで販売ページのHPデザインまで挑戦中。LINEスタンプ販売は今、副業として実際に増えている領域。

スキル登録（Claude Code のショートカット必殺技）

「ヒアリング → 提案書作成」「動画 → 要約」みたいな定型フローを"スキル"として登録しておくと、リンクを貼って「このスキルでやって」とひと言で全工程が走る。何度もやる作業がある人ほど効く機能。

6 会で出た Q&A（全問掲載）
Codex だけ使ってる。Claude Code まで使う必要ある？
基本どちらか1個で十分。Codex のほうが画像生成内製・プロプラン枠の広さの面で先行している。両方触れるなら触ったほうが選択肢は広がるけど、義務ではない。
LINE を AI に操作させるのって、API キーが要るの？
LINEの個別チャットには公開された API/MCP が存在しないので、API キーで操作する方法は基本ない。代わりに「パソコンの LINE 画面そのものを Codex/Claude in Chrome に操作させる」やり方になる。API/MCP が用意されているツール（Slack等）は、画面操作よりそちら経由の方が動作が軽い。
Claude Code で開発するなら、最初に GitHub も設定すべき？
必須じゃない。バージョン管理が必要になったタイミングで入れればOK。Claude Code に頼めば GitHub 操作も全部やってくれる。ただし誤って全世界に公開してしまうリスクがあるので、リポジトリの公開設定だけは要注意。
いちいち「許可しますか？」を押すのが面倒。聞いてほしいものと聞かなくていいものを分けたい。
プロプランは基本「全部聞く」or「全部スルー（バイパス権限モード）」の二択。Max プランだと自動モードが使えるので、ここを刻みたい人は Max を検討。メモリ機能で「下書きレベルは確認不要」と教育していくこともできる。
NotebookLM と Claude Code、両方使うの大変。どう使い分ければいい？
現状この2つは連携しづらい。Claude Code は過去のやり取りを記憶に積んで「育てていく」運用が強み。「育てたい用途は Claude Code に寄せて、リサーチ系は NotebookLM」など、使いやすい方に寄せていいというのが会の見解。
会社で AI を使うとき、何を入れていいか・何を入れちゃダメか分からない…
会終盤でこの話に時間を取りました。一般公開情報・名前程度は AI 入力OK。マイナンバー・健康情報は絶対NG。学習オフ設定でも完全には安心できない、というのが現実解。詳しい線引きは下のブランチページにまとめてあります👇
