「IRODORIの請求漏れ・入金確認漏れを、Claude Code 介入で解決できるか？」

1. 背景・経緯

① IRODORIが抱えている経理オペレーション課題

  • 請求書発行漏れ・入金確認漏れが頻発（小林さん案件で3ヶ月未入金に気付けなかった実害発生）
  • PM（請求発行）／営業（案件管理）／経理（入金確認）が分散管理で責任曖昧
  • 月額変動案件（例：あけみさん「今月10万・来月15万」型）の追跡困難
  • マネフォ「請求書一覧」機能を活用しきれていない
  • 経理担当が 2年で3人→2人に減少＋業務量は増加しており、人手が足りない状況

② 相談の流れ（事実）

2. 中村さんからのご提案

マネフォを請求情報の元データとして、Claude Code が橋渡しの役を担い、Notion の請求管理データベースで一元管理する、という構成です。

┌──────────────┐ │ マネフォ │ ← 請求書発行の元データ └──────┬───────┘ （請求日・請求額・顧客名・支払期限） │ ① 外部ツール連携の仕組み（MCP）で │ データを取り出す ▼ ┌──────────────┐ │ Claude Code │ ← AI が橋渡し └──────┬───────┘ （顧客名の紐付け・確認の問いかけ・例外判定） │ ② Notion 側に自動で取り込む ▼ ┌──────────────┐ │ Notion 請求 │ ← 日常の運用画面 │ 管理データ │ （経理一括管理・状態の移り変わり・支払期限の通知） └──────────────┘

ミーティングで合意した付帯事項

  • 状態の移り変わり：新規 → 見込み（金額未確定）→ 確定（マネフォ発行済）→ 請求書未発行（旧「未請求」を改名）→ 入金済
  • 顧客名の紐付け：マネフォと Notion の顧客名がズレた時は、AI が「これで合っていますか？」と確認しながら進める形（完全自動化ではなく、人の確認を挟む）
  • 業務の集約方針：PM・営業・経理に分散していた請求業務を、経理側で一括管理する方向へ

3. 技術的にできるかどうか — ✅ できます

✅ 可
マネフォ公式の MCP サーバー（2026年3月26日 から全プランで提供開始）を使えば、接続設定だけで Claude Code からマネフォの仕訳・請求書・帳簿データを操作できます。

① 公式 MCP サーバーの確認事項

  • 提供開始：2026年3月26日（約3ヶ月前）
  • 提供範囲：マネフォの全プラン（以前は会計事務所など一部限定だった機能を全面解放）
  • 提供形態：クラウド側に置かれた MCP サーバー（利用者側で環境構築は不要・接続設定のみ）
  • 対応 AI ツール（公式記載）：Claude Desktop ／ Claude Code ／ Claude Cowork ／ Cursor ／ Gemini CLI
  • 認証：認証連携（OAuth）方式（詳細は公式の開発者向けページで要確認）

② 使える機能

  • 仕訳の作成（AI が自然な日本語で仕訳を作成）
  • 帳簿の検索（元帳・補助元帳から取引を検索）
  • データの確認（残高・推移・科目別集計）
  • 各種レポートの作成（試算表・損益計算書・貸借対照表 など）

③ つなぎ方のイメージ

Notion MCP と同じく、認証連携と接続設定のみで利用可能。Claude Code 側にマネフォの接続情報を登録すれば、「請求書一覧の取得」「顧客マスタの取得」「仕訳の追加」などが可能になります。

4. 運用する上での注意点 — ⚠️ 確認・整理が必要

⚠️ 要確認
技術的にできることと、実際の運用設計は別の話です。
本番運用に進む前に、以下の点について事前に確認・整理しておきたいと考えています。

確認しておきたい 5つの点

① どのアカウントで動かすか

三又は IRODORI とは業務委託契約の関係にあるため、三又個人のアカウントで IRODORI（別会社）の経理データを扱う形にする場合、契約・規約上どの位置づけになるか、事前に整理が必要です。

② マネフォへのログイン権限

現時点で三又は IRODORI のマネフォログイン権限を持っていません。 もし接続する形を取るなら、(A) IRODORI 公式のマネフォアカウントから権限を付与いただく、(B) 読み取り専用の権限を切り出していただく、などの調整が必要になります。

③ 機密データの取り扱い範囲

マネフォには 取引先・取引金額・銀行口座・税理士情報 など、経理の元情報が集約されています。 AI とのやりとりを通す関係上、「どの範囲のデータを AI に渡すか」「会話記録をどう管理するか」を事前に決めておく必要があります。 （※ Claude の月額契約経由の利用は AI 学習対象外と公式に明示されていますが、運用上のログ管理は別の論点として整理が必要です）

④ 誤って書き込んだ時の戻し方

AI が仕訳を書き込んだ場合、誤入力時に「誰が・どう戻すか」が不明確になりがちです。 最初は読み取りだけから始める／書き込み前に下書き層を挟む／人の確認を必ず通す、など段階を踏んだ設計が必要です。

⑤ 個人アカウント経由にした場合の双方向リスク

仮に三又の個人アカウント経由で接続する形を取る場合、万が一個人アカウント側に何かトラブルが起きると、IRODORI の経理データにも影響が及ぶ構造になります。 個人側にとっても会社側にとっても、双方向にリスクが残る形になる点は、事前に共有しておきたい論点です。
