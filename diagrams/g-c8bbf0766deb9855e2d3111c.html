Everyday flow

普段の流れは、4ステップ

録画はZoom、文字起こしはNotta。役割を分けて扱うので、録画の完成を待たずに文字起こしが取れた時点から整理できます。

01

Zoomを開始

普段どおり会議を始めます。録画の有無とNotta文字起こしは別です。

02

Notta Botが参加

参加者として表示されます。録音の同意・許可は利用者側で行います。

03

会議を終了

Nottaの状態がTranscribedになれば、公式CLIから本文を取得できます。

04

Codexへひとこと

決まった起動文を送ると、対象照合→下書き→保存後確認まで進みます。

あとは結果を待つだけ

Codexが既存Skillを勝手に上書きせず、CLI・認証・出力テンプレートの状態と、必要な次の1操作を返します。

Codexが内部で確認する内容

CodexはZIPを一時フォルダへ展開し、同梱された専用入口を読んでSkillを配置します。その後、Node.js・npm・Notta CLIの有無、CLIの版、Nottaへの接続、確認済み出力テンプレートのSHA-256を読み取りで確認します。Salesforceを使っている場合は、利用可能な接続経路だけを診断し、顧客データには書き込みません。既存Skillが異なる場合は上書きせず停止します。

Salesforceにも記録したい場合

導入先のCodexへ次の文を送ると、公式Hosted MCP Serverを第一候補に、API・CLI・ログイン済みChromeまで利用可能な経路を確認します。診断中はSalesforceへ書き込みません。

このPCのCodexからSalesforceへ接続できる既存経路を、設定変更や書き込みをせずに確認してください。優先順は、①Salesforce公式Hosted MCP Server（SObject Mutationsなど）、②Salesforce公式APIまたはSalesforce CLI、③ログイン済みChrome拡張です。現在利用可能な経路、Salesforce管理者による有効化が必要なもの、本人に必要なログイン・OAuth操作を分けて、いちばん簡単で安全な導入案を報告してください。接続方法と記録先が確定するまでは、顧客データの作成・更新・削除をしないでください。

Safety by default

勝手には行いません

  • Zoom録画やNotta Botの自動参加設定
  • 会議の常時監視・無限リトライ
  • 複数候補からの推測選択
  • メール・チャット送信、共有、公開
  • 会話にない数字・担当・期限の補完
  • 商談フェーズの範囲表記や、根拠のない先の段階へのチェック

Delivery shape

まずSkill、固まったらPlugin

小さく受入テストしてから配布形式を広げるのが、今の段階ではいちばん安全です。

今回のおすすめ

単体Skill＋導入HTML

ZIPで渡して相手のMacへインストール。仕組みが透明で、確認済みテンプレートの将来更新や1件目の受入修正が簡単です。

  • 今すぐモック確認できる
  • 明示起動で安全
  • GitHub Pagesにも置ける
運用確定後

Pluginとして配布

複数人へ同じSkillを配る、コネクタも同梱する、更新を一元化する段階でPluginへ昇格します。

  • 配布と更新を揃えやすい
  • ChatGPT / Codexで利用範囲を広げられる
  • 公開前の審査・権限設計が必要
公式仕様との対応を見る

OpenAI公式では、Skillは SKILL.md と任意のscripts／references／assetsで構成され、明示起動と暗黙起動に対応します。ローカルSkillは $HOME/.agents/skills から読み込まれ、他者への再利用可能な配布はPlugin化が推奨されています。OpenAI公式「Build skills」
