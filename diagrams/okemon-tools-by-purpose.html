CORE BELIEF
「何を繋ぐか」より、
「今、解決したい課題に繋げられるか」。

→ 流行ってるから入れる、有名だから入れる、はやらない。
「いま、自分の手元に困ってる業務がある」→「それを楽にできるツールを後から探す」だけ。

01

4つの実務シーン × 使ってるツール

DAILY USE CASES
MCP ローカル設定（claude.json） CONN 公式コネクタ（GUIでオン） API 直接利用（環境変数） EXT Chrome拡張系

① 議事録・文字起こしを残したい

SCENE 01 — RECORDING & TRANSCRIPTS
MCP Circleback
オフ会・MTGの自動議事録。Zoom録音→文字起こしを Vault に原液保存。今日の21時もこれで。
API YouTube Transcript
YouTube動画の文字起こしを取得。学長ライブ・他人セミナーを自分用ノウハウに転換する起点。
API Groq（要約担当）
取れた文字起こしは自分で読まずにGroqへ。llama-3.3-70bで爆速要約→活用事例リスト化。
REAL VOICE — 普段の流れ オフ会終わり → Circleback処理待ち2-3時間 → Transcript取得 → Vaultの「コンテキスト/トランスクリプト原液/」へ保存 → Groqで要約 → 担当フォルダに格納。「自分の声以外も自動で残る」のが一番の安心ポイント。

② Google系で情報を取りたい・動かしたい

SCENE 02 — GOOGLE WORKSPACE & YOUTUBE
CONN Gmail
受信検索・整理。クライアント連絡・税理士・弁護士まわりは公式コネクタで安定。
CONN Google Calendar
予定参照・自動登録。面談・債権者集会・旅行も全部ここ経由。
CONN → API Google Drive
公式コネクタはエラー多め。最近は直接Drive APIを叩く方向に切替。
API YouTube Data
動画リサーチ・チャンネル分析の最近のメイン。学長ライブまわりで毎日触ってる。
REAL VOICE — 公式コネクタ→直APIへ移行した話 公式コネクタで「Drive全部操作できます！」って書いてあるけど、実際は結構エラー出る。試して限界を感じたら、用途別に直接APIを叩く構成に変える。これは「コネクタが悪い」んじゃなくて、自分の用途が公式想定を超えただけ。

③ 業務チャットを自動で動かしたい

SCENE 03 — BUSINESS CHAT AUTOMATION
MCP Chatwork
業務委託先のPMチャットへの日次自動投稿（朝礼ダッシュボード等）。会話操作も可能。
API Chatwork（Webhook）
GitHub Actions cron 16:00 から直接POST。Pythonスクリプト化済。
CONN Slack
リベシティ外で使うことあり。最近は出番少なめ。「使うときだけ触る」が原則。
REAL VOICE — ジワジワ効くやつ Chatwork APIは普段使いの実務にいちばん効いてる。毎日同じ報告作業をAIに任せられる感動が大きい。「報告書きたくない病」のADHD当事者にとって、これがあるだけで業務が回る。

④ 大量データを要約したい・自分で読みたくない

SCENE 04 — LARGE DATA SUMMARIZATION
API Groq（llama-3.3-70b）
巨大なJSON・トランスクリプト・Notionデータを丸ごと投げて要約。速度爆速・無料枠で十分回る。
MCP Notion（個人 / 業務委託先）
2系統運用。絶対混ぜない。業務委託先専用MCPと個人用MCPはガードレール明記。
MCP Apple Notes
Mac標準メモを自動取り込み・整理。手書き入力のモバイル走り書きをVault連携に。
MCP fal.ai
画像・動画生成系の試作。用途を絞って使ってる。
REAL VOICE — Groqルール 「大量データはClaude本体に読ませない、Groqに投げる」が鉄則。トークン節約＋速度＋コスト全部解決。「自分で読まない、AIに読ませる」を徹底したら、扱える情報量が10倍になった。

⑤ ブラウザを直接操作したい（おまけ）

BONUS — BROWSER AUTOMATION
EXT claude-in-chrome
本人ログイン中の実Chromeを直接操作できる公式拡張。リベシティ画面・GitHub Actions・スプシCSV取得まで。
REAL VOICE — トークン消費の桁が違う 以前 Playwright MCP を試したらトークン爆食い＋暴走前科あり。実Chrome経由だとログイン作業ゼロ・桁違いに省トークン。デフォルトで使ってる。
02

選び方の3原則

DESIGN PRINCIPLES
PRINCIPLE 01

「やりたいこと」が先、ツールは後

流行ってるから入れる、はやらない。困ってる業務が出てきた時にだけ入れる。先入れ禁止、後付けOK。だからツール棚には飾りがない。

PRINCIPLE 02

まずコネクタ、ダメなら直API

公式コネクタはポチっと押すだけ。これが最初の一歩。限界を感じたらピンポイントでAPI直叩きへ。Driveで実際に経験した移行ルート。

PRINCIPLE 03

APIキーは必ず環境変数に

設定ファイル・スキル本体に直書き禁止。すべて ~/.zshenv に集約。学長の呪文でAPIキー漏洩は AI が消してくれるけど、最初から書かないのが一番。

03

オフ会で出た質問への回答

QUESTION FROM 2026-05-07
Q | 会場参加者 おけもんは普段、どんなコネクタ・MCP・APIを使ってるんですか？
使ってるのはローカルMCP 4個 / 公式コネクタ 9個 / 直接API 7個 / Chrome拡張 1個。
ただし 「これだけ使ってますよ自慢」じゃない。

実際の使用頻度は ①Circleback（議事録）／②Google系＋YouTube Data API（リサーチ）／③Chatwork（自動投稿）／④Groq（大量データ要約） の4本柱に集中。

公式コネクタが不安定なやつ（Google Drive）は直APIに切り替え。最近YouTubeリサーチが増えてきたからYouTube Data APIとTranscript APIの出番が爆増。

結論：「何を繋ぐか」より「今解決したい課題に繋げられるかどうか」。
その視点で選んでいくと、棚に飾りがなくなる。全部実戦投入されてるやつだけが残る。
