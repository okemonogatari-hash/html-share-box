CHAPTER 01

第1章｜second brain の4派閥、どんなフォルダ作ってる？

あおいが机に並べたのは、世界中で実際に運用されている second brain の代表的な4派閥。順番に見ていく。

SCHOOL 01 ／ LLM-NATIVE

① Karpathy 派 — raw/ ＋ AGENTS.md だけ

元 OpenAI / Tesla AI の Andrej Karpathy が 2026-04-02 に公開した方式。本人いわく「super simple and flat」。100記事 / 約400K words 規模で運用中。

my-vault/
├── raw/               ← Web Clipper で取ってきた素材
├── AGENTS.md          ← schema をここに一元化（LLMが読む案内図）
├── 〇〇.md             ← 普通の記事ノート
├── 〇〇.png
├── 〇〇.csv
└── 〇〇.py             ← nested directory（必要なだけ階層化OK）
★ 根拠①｜LLM が書く・リンクする・index をメンテする
"I use an LLM to incrementally 'compile' a wiki ... The wiki includes summaries of all the data in raw/, backlinks, and then it categorizes data into concepts, writes articles for them, and links them all."

「LLM を使って wiki を少しずつ "compile" する。wiki には raw/ の全データの要約、backlinks が含まれ、データを概念ごとに分類して、記事を書いて、全部リンクで繋いでくれる」

— Andrej Karpathy, 2026-04-02 (source)
★ 根拠②｜schema は AGENTS.md に一元化
"...it's just a nested directory of .md files and .png files and a few .csv and .py, and the schema is kept up to date in AGENTS.md. The LLMs get this very easily."

「ただの .md / .png / 少しの .csv / .py のネストしたディレクトリで、schema は AGENTS.md に最新の状態で保ってる。LLM はこれを難なく理解する」

— Andrej Karpathy, 2026-04-02 (source)
核心：raw/ に素材を放り込み、wiki本体は .md/.png/.csv/.py のネストしたディレクトリ。backlinks の生成・カテゴライズ・記事間リンクは LLM が自動でやる。schema は AGENTS.md に一元化されていて、これが LLM 向けの案内図として機能する。
SCHOOL 02 ／ ACTION-DRIVEN

② PARA 派 — 4つのトップフォルダだけ

Tiago Forte が "Building a Second Brain" で提唱。アクション性の高さで4階層に分ける。世界で最も普及してる second brain フォルダ設計。

my-vault/
├── 1-Projects/       ← 今動いてる案件（締切あり）
├── 2-Areas/          ← 継続的に責任を持つ領域（健康・財務など）
├── 3-Resources/      ← 興味のあるトピックの参考資料
└── 4-Archives/       ← 終わったもの・休眠してるもの
核心：「このノートに、いつアクションを取るか？」で配置場所が決まる。動くなら Projects、責任継続なら Areas、参照だけなら Resources、終わったら Archives。テーマ別じゃなくアクション性別に切る。
SCHOOL 03 ／ REFINERY-STAGE

③ 番号付き派（Khairallah / テツメモ系）— 0〜3の精製ライン

Khairallah が広めた「refinery stage（精製工程）」フォルダ。日本でもテツメモ氏など実践者多数。ノートが熟成していく流れそのものをフォルダで表現する。

my-vault/
├── 0-raw/         ← 取り込んだだけ・未消化（原液）
├── 1-desk/        ← 今いじってる作業机
├── 2-atoms/       ← 1ノート1概念に分解した最小単位
├── 3-threads/     ← atom同士を繋いだ "考えの糸"
├── sources/       ← 出典・参考文献
└── briefings/     ← LLM向けの簡潔まとめ
核心：0→1→2→3 と ノートが昇格していく流れがフォルダ名そのもの。「今このノートは何段階目？」を一目で把握できる。LLM 時代を意識した sources/ と briefings/ が現代的。
SCHOOL 04 ／ NO-FOLDER

④ LYT / no-folder 派 — フォルダゼロ・MOC でリンク主義

Nick Milo の LYT（Linking Your Thinking）と、古典 Zettelkasten・Andy Matuschak の系譜。フォルダで分類することそのものを拒否。代わりに MOC（Maps of Content）という「目次ノート」をハブとして使う。

my-vault/
├── 20260629-001-second-brain.md   ← 連番ID＋タイトル
├── 20260628-001-folder-design.md
├── 20260627-014-link-everything.md
├── MOC-知識管理.md                ← 関連ノートへの [[]] が詰まった目次
├── MOC-おけ森運用.md
└── MOC-健康習慣.md
（フォルダは1つも切らない。全ノートがフラットに並ぶ）
核心：「分類すると、繋がりが見えなくなる」が思想の中心。1ノート1概念で書いて、[[ ]]リンクと MOC（目次ノート）だけで構造を浮かび上がらせる。フォルダを切った時点で、それ以外の繋がりが死ぬ、と考える。
☀️ ひより 4つ並べると違いが見えるの〜。① Karpathy は LLMに全部任せる、② PARA は 動くか動かないか、③ 番号付きは 熟成段階、④ LYT は フォルダ無し ……それぞれ別物に見えるけど？
🐱 あおい ……だよね。じゃあ次、共通項を見にいく。
CHAPTER 02

第2章｜共通項は「リンクで繋ぐ」だった

4派閥を並べると、見た目はまったく違う。でも見方を変えると 同じ1つの設計思想 が見えてくる。

★ Karpathy 一次ソース①｜メイン投稿（schemaの保ち方）
"Currently no because I'm trying to keep it super simple and flat, it's just a nested directory of .md files and .png files and a few .csv and .py, and the schema is kept up to date in AGENTS.md. The LLMs get this very easily. Any custom functions are easy to vibe code tools for."

「今のところそうしてない（＝特殊なツールは使ってない）。super simple かつ flat に保とうとしてて、ただの .md / .png / 少しの .csv / .py のネストしたディレクトリだよ。schema は AGENTS.md に最新の状態で保ってる。LLM はこれを難なく理解する。カスタム関数が必要になっても、vibe coding でツールを書けばすぐできる」

— Andrej Karpathy, 2026-04-02 (source)
★ Karpathy 一次ソース②｜メイン投稿（LLMがwikiを書く・リンクする）
"I index source documents (articles, papers, repos, datasets, images, etc.) into a raw/ directory, then I use an LLM to incrementally 'compile' a wiki, which is just a collection of .md files in a directory structure. The wiki includes summaries of all the data in raw/, backlinks, and then it categorizes data into concepts, writes articles for them, and links them all."

「ソース文書（記事・論文・リポジトリ・データセット・画像など）を raw/ ディレクトリに index する。そこから LLM を使って wiki を少しずつ "compile" する。wiki は単なる .md ファイル群（ディレクトリ構造）。wiki には raw/ の全データの要約、backlinks（被リンク）が含まれ、データを概念ごとに分類して記事を書き、それらを全部リンクで繋いでくれる」

— Andrej Karpathy, 2026-04-02 (source)

注目ポイントは2つ。① schema（構造の決まりごと）は AGENTS.md にだけ書いて、フォルダで表現しない。② backlinks の生成・カテゴライズ・記事間リンクは LLM が自動でやる。Karpathy 自身は raw/ に素材を放り込むだけ。

そして PARA・番号付き派・LYT も、見方を変えると 同じ思想を共有している。フォルダで縦に積むんじゃなく、リンクで横に繋ぐ。

4派閥に共通する3つの態度

  • ① フォルダは "粗い分類" 用に少なめに保つ（流派により多くて4つ・少ない例だとゼロ）
  • ② ノート同士の関係性は [[リンク]] で表現する（フォルダ階層に押し込めない）
  • ③ ハブ（AGENTS.md / index / MOC）から辿れるようにする（フォルダ階層を覚える代わりに、入口ノートから辿る）
🎤 はるか えっ、これ……うちのおけ森の 00_ROUTER → STATE.md → 関連MD って、まさに 「ハブから辿る」そのものじゃない！？ てへぺろ、知らんうちにやってた！💦
🐱 あおい ……そう。CLAUDE.md にも「リンク=フック・忘れても取り返せる構造」って書いてある。これ、4派閥の共通項と完全に同じ思想。
おけ森は既に LYT × PARA のハイブリッド をやってる。CxOフォルダ＝Areas、PJフォルダ＝Projects、コンテキスト＝Resources、セーブポイント＝Archives。
☀️ ひより おお〜、おけ森も second brain の正統派なの〜！ 知らないうちにプロと同じことしてたの〜！
CHAPTER 03

第3章｜で、結局どれがいいの？ — 3つの共通ルール

はるかが一番聞きたい問い。「で、結局どれがいいの？」。あおいの答えは「どれでもいい。ただし3つだけ守れ」。

01

フォルダは増やしすぎない

フォルダ多い派（PARA・番号付き派の4階層）／少ない派（Karpathy の1階層）／使わない派（LYT のゼロ）と、流派ごとにスタンスは違う。それでも共通してるのは、「フォルダで分類しすぎないこと」。トップ階層がどんどん膨らんでいくと、置き場に迷うノートが増える。新しい分類軸を増やしたくなったら、フォルダを足す前にリンクや MOC で表現できないかを一度考える、というのが共通する態度。

02

テーマで分類しない、状態で分類する

PARA はアクション性、番号付き派は精製段階、Karpathy は raw か否か、LYT はそもそも分類しない。どの流派も "テーマ別フォルダ" を中心に据えていないのが特徴。「健康フォルダ」「お金フォルダ」「仕事フォルダ」のようなテーマ別フォルダは、複数テーマにまたがるノートの置き場に困りやすい。テーマは タグや MOC（目次ノート）で表現するのが、共通する一つの解。

03

入口ノート（ハブ）から辿れるようにする

Karpathy = AGENTS.md、PARA = README / Index、番号付き派 = briefings/、LYT = MOC。どの流派も「ここから読み始める入口ノート」を1つ用意しているのが共通項。フォルダ階層を覚える代わりに、入口ノートから [[リンク]] でたどっていく。おけ森でいう 00_ROUTER ＋ 00_PJ台帳 ＋ STATE.md がまさにこの位置づけ。

🎤 はるか ……てへぺろ💦 うちのVault、「健康習慣」「マネー戦略」「学び」みたいなテーマフォルダ何個か作ってた気がする……
🐱 あおい ……ふむ。あるあるだね。
テーマフォルダを作っちゃうと、「健康とお金が両方関係するノート」 が置き場に困る。second brain のプロが避けたい構造はこれ。
テーマで分けたい時は タグか MOC（目次ノート） でやる。
CHAPTER 04

第4章｜明日の小さな一歩・3ステップ

ひよりの大好物、「明日できることに落とし込む」のコーナー。フォルダ全部組み直すんじゃなく、明日の朝の10分でできる3ステップだけ。

STEP 01 ／ 10 minutes

トップフォルダを数えてみる

まず自分の Vault のトップ階層を数えるだけ。5つ以上あったら、迷子になりやすいサイン。慌てて統合しなくていい、「いま自分は5つ以上のテーマで生きようとしてる」と気づくだけが目的。

# macOS の Finder か Obsidian 左ペインで数えるだけ。 # おけ森なら： ls -d "000 おけ森"/*/ | wc -l
STEP 02 ／ 10 minutes

入口ノートを1個だけ作る

Vault の 一番上に「00_入口.md」を1つ置く。中身は「最近触ったMD 5本」のリンクだけでいい。これが MOC（目次ノート）の原型。明日の自分が迷子になっても、ここから辿れる入口を1つ持つ。

# 00_入口.md の例 # 最近触ったノート - [[2026-06-29 デイリーログ]] - [[ぷかり運用ガイド]] - [[ふくまめさん取説]] - [[家計収支表]] - [[読書ノート_Day013]]
STEP 03 ／ keep going

新ノートを作る前に、まず [[既存ノート]]に追記できないか考える

フォルダを増やす前にリンクを増やす。新規ファイル作る前に「既に近いノートあるんじゃない？」と一度grepする。あれば追記、なければ作る。これだけで "フォルダだけ立派で中身スカスカ" 問題が消える。

# 着工前の30秒チェック grep -ril "second brain" "000 おけ森/" | head -5 # 既存ノートが出てきたら、まずそこに追記を検討
☀️ ひより これなら明日の朝10分でできる〜！ 「Vault組み直し計画」じゃなくて、入口ノート1個作る だけなの〜。完璧にしようとしないのがいい日和〜！
🎤 はるか えっ待って、これ おけ森の [[森の入口]] そのものじゃん！？ てへぺろ💦 もう持ってたのに気づいてなかった〜！
🐱 あおい ……うん。
＜ある＞のと＜使ってる＞のは別。
でも、＜ある＞時点で半分終わってる。
