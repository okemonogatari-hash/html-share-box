Codex Computer Use
はじめの一歩

画面を見て、ボタンを押し、結果を読み返す。そんなPC操作をCodexに頼む機能です。まずは自分の画面で、小さな新規文書を使って確かめましょう。

まずは、あなたのCodexに診断を頼もう下の診断プロンプトをコピーして、確認したいパソコンのCodexに貼ってください。設定が足りなければ、画面を見ながら一つずつ進めます。OSの許可画面だけは本人が操作します。

まずはこの順で、ひとつずつ

「使えるか」から「保存して開き直せたか」まで

  1. STEP 01機能があるかデスクトップ版・地域・組織の提供状況を確認
  2. STEP 02使う経路を選ぶ画面操作とChrome拡張は別の経路
  3. STEP 03本人が許可するOSの許可が表示されたら内容を見て判断
  4. STEP 04無害な操作を試す新規文書に短い日本語を一度だけ入力
  5. STEP 05結果を読み戻す画面・本文・保存後の再オープンを確認

02

設定チェック：使う経路とOSを確認

画面操作とChromeのページ読み取りは別の機能経路です。まず、何をしたいかに合わせます。

共通：デスクトップ版のComputer Use

あなたのOSに合わせて表示

Mac：本人が許可画面を確認

公式案内では、macOSの System Settings → Privacy & Security で、画面収録（表示が「画面とシステムオーディオの録音」等の場合もあります）と、Codex Computer Useのアクセシビリティ許可を確認します。表示されたアプリ名と許可内容を本人が見て操作してください。

公式資料はMacでのバックグラウンド動作に対応すると案内していますが、今回その状態は実測していません。画面収録とアクセシビリティは別の許可です。

Windows：ロック解除した前景デスクトップで試す

公式案内では、WindowsのComputer Useはアクティブなデスクトップ上で動きます。最初の確認ではPCのロックを解除し、操作中に本人が同じ画面やマウスを同時に動かさないようにします。

Mac向けの「画面収録」「アクセシビリティ」の手順を、そのままWindowsへ当てはめないでください。

ブラウザ本文を読む：Chrome拡張の経路

ページを読む依頼なら、Settings → Computer Use → Chrome → Install から公式拡張を入れ、Manageの表示と、拡張を入れたChromeプロファイルを確認します。Codexでは@Chromeを選びます。@Browser（内蔵ブラウザ）とはログイン状態が別です。

Chromeの接続テスト：入力欄の「@」からChromeを選び、「https://learn.chatgpt.com/docs/computer-use を開き、ページの見出しを教えて。フォーム送信や設定変更はしないで」と依頼します。公開ページを読めたら、次に必要なサイトへ本人がログインして試します。

Full access は別の設定です。 Codexのファイルやコマンドの実行範囲を指し、macOSの画面収録・アクセシビリティ許可や、アプリ・サイトごとの許可とは別レイヤーです。画面操作のためにすべての許可を広げる必要はありません。

このページのチェック状態やOS選択は保存しません。サーバー送信、Cookie、localStorageへの記録は行いません。読み込み時はチェックを空に戻し、Macの手順を表示します。

03

症状から切り分ける

同じ操作を連打せず、最新画面を見直して次の一手だけ試します。読みたい項目を開いてください。

Computer Useがメニューに見当たらない

機能の提供は地域や組織設定によって異なる場合があります。まずChatGPTデスクトップアプリのWork/Codexにいるか、Plugins内のComputer Use、Settings → Computer useを見直します。

項目がなければ、管理者や公式の提供案内を確認します。手で設定ファイルを書き換えたり、非公式インストーラーを探したりせず、利用可能になるまで待ちます。

スクリーンショットは取れるのに、クリックやスクロールが失敗する

画像を取得できたことは、次の操作が通った証拠にはなりません。同じアプリを本人や別のAIが同時に操作していないか確認します。操作中なら待ち、いったん止めて最新画像を取り、ボタン名と役割・位置を見直し、別の小さな操作を一度だけ試して結果を読み戻します。

  • noWindowsAvailable：エラー後に画面を取り直し、ダイアログや対象アプリが変わっていないか確認。続けて同じクリックを重ねません。
  • invalid element ID：画面が変わった後の古い部品IDの可能性があります。最新画面から部品を取り直します。
  • 10月1日は画面を取り直してスクロールできた記録があり、10月6日は通常画面でスクロールが失敗しました。前回の成功を今回の画面に当てはめず、原因も一つに決めません。
日本語が入らない、または入力先が違う

操作前に画像で入力欄と既存の文字を確かめます。まず新規の空文書を使い、一文だけ貼り付けて、操作後に画像と読み取りの両方を確認します。既存文書の上書きは試験に使いません。

文字が見えなければ、欄と画面をもう一度確かめてから一度だけ別の入力方法を試します。失敗が続いたらそこで止め、エラーの原文を残します。

入力は見えたが、保存できたか分からない

入力の成功と保存の成功を分けます。保存先が本人から指定されていなければ先に尋ねます。新しいファイル名を使い、同名ファイルがあれば置き換えず別名を確認します。

画面が変わった、保存ボタンが反応しない、エラーが出た場合は最新画面を読み直します。ファイルが保存先に存在し、開き直して同じ文章が読めるまで「保存済み」と言いません。

今回のTextEditでは「保存」操作でエラーとなり、指定先にファイルはありませんでした。日本語入力は確認できましたが、保存と再オープンは未確認です。

Chrome拡張が接続されない、または違うページが見える

画面操作の許可と、Chrome拡張の接続を混ぜずに確認します。@Chromeを選んでいるか、拡張を入れたChromeプロファイルか、Settings → Computer Use → ChromeのManageに拡張が出るかを見ます。@Browserには別のログイン状態があります。

まだ直らない場合は、公式案内に沿って次の順に進みます。

  1. 対象サイトのブロックリストを確認。
  2. デスクトップアプリの更新と、重複するアプリがないか確認。
  3. 未保存作業を保存し、Chromeを再起動。Manageとプロファイルを再確認。
  4. 新しいチャット、次にデスクトップアプリ再起動を試す。
  5. 最後に、公式のInstall手順で拡張を入れ直す。解決しなければアプリで /feedback を使い、チャットIDと発生したエラーをサポートへ伝えます（秘密情報は除きます）。

ローカルファイルのアップロードをする場合を除き、file URL許可を追加する必要はありません。

Macの許可を求められた／Windowsの画面が反応しない

Macは許可画面のアプリ名と用途を本人が読み、必要な項目だけ本人が操作します。AIがセキュリティ許可を代わりに承認することはできません。全許可のリセットや一括オンを対策にしません。

Windowsはロック解除したアクティブなデスクトップで試します。ロック中や、別画面へ切り替えた状態を初回テストにしません。操作中の同時入力を避けます。

04

そのままCodexに貼れる診断プロンプト

貼り付け先は、確認したいPCで開いたCodexです。入力欄で「@」を入力し、Computer（または対象アプリ）が出たら選んでから、下の文を貼り付けます。候補がない場合は先に設定チェックへ。許可設定と保存先は本人が判断します。

Computer Useの設定と、無害な新規文書テスト

このPCでCodex Computer Useを安全に診断してください。現在の状態を確認してから、一つずつ進めてください。

最初に次を調べ、分かる範囲で報告してください。
- OS名とバージョン、ChatGPT/Codexデスクトップアプリのバージョン
- Computer Useの機能・操作ツールがこのチャットで実際に使えるか
- 画面操作を試す対象アプリ。Chromeを試す場合は、Chrome拡張がつながっているプロファイルと、@Chromeを選べるか
- 同じアプリを本人や別のAIが同時に操作していないか。操作中なら、画面を取り合わず終わるまで待つ

操作前に最新のスクリーンショットを見て、対象画面と入力欄を確認してください。画像を取得できただけで、クリックや入力が成功したとは判定しないでください。

機能やツールが使えない場合は、その事実と確認場所を伝えて止まってください。設定ファイルの手編集、非公式な導入、制限や許可の回避はしないでください。OSの画面収録・アクセシビリティなどの許可が必要なら、設定画面と項目名を一つずつ案内し、本人が内容を読んで操作するのを待ってください。あなたが許可を代わりに承認してはいけません。

テストは新しい空の文書だけで行います。MacならTextEdit、Windowsならメモ帳を使い、既存の文書は開いたり変更したりしないでください。最新画面で新規書類を確認してから、次の2行を一度だけ入力してください。
Computer Use 動作確認
日本語の入力を確認しました。

入力後、スクリーンショットと画面からの読み取りの両方で、欄と2行の内容を確認してください。一致しなければ成功と言わず、最新画面を取り直して一度だけ別の小さな入力方法を試します。同じエラーが続いたら止め、原文を記録してください。invalid element IDが出たら最新画面から部品を取り直します。

保存テストに進む前に、私に保存先フォルダを尋ねて回答を待ってください。指定された場所に新しいテキストファイルとして保存します。同名ファイルがあれば置き換えず、別名を決めるため私に尋ねてください。保存ダイアログや画面が変わったら最新状態を再確認してください。保存先にファイルがあることを確認し、開き直して2行が一致するまで保存成功と報告しないでください。

最後に「成功」「失敗」「未確認」を分けて短く報告してください。失敗時はエラー原文、最後に見えた画面、次に試す一手を添えてください。メールアドレス、認証情報、個人のファイル内容、アカウントIDは報告へ含めないでください。許可が得られない場合や同じ失敗が続いた場合は、その操作を止めてください。

コピーが失敗した時は成功表示を出しません。本文を選択して手動でコピーできます。

05

どこまで確かめたら「動いた」？

「動いた」は一言で済ませず、実際に確認できた段階を伝えます。

① 機能が見つかった

このPC・アカウントで設定項目とツールが使える。

② 操作が実行された

画面上の対象と操作後の変化を観測できた。

③ 入力を読み返せた

画像と画面の読み取りで、期待した文字が一致した。

④ 保存後も一致した

新規ファイルを保存先で確認し、開き直して同じ文章を読めた。

今回の実測は②と③の一部まで。 新規文書への日本語入力は確認できました。保存ファイルが作られず、④は未達です。Chrome拡張のページ読み取り成功は、TextEditの保存成功を意味しません。

画面が撮れた・ボタンを押したと言った、だけでは完了にしません。操作結果と保存結果を、それぞれ読み戻して伝えます。
