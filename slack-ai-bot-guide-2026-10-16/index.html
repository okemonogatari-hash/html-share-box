SlackでClaudeのAPIを使って
Botを作る方法

例として作ったのは「ストレングスファインダーのことを、キャラクターが資料をもとに答えてくれるbot」。半日で動くところまで作った記録を、仕組み・費用・手順・コード・つまずいた所まで、そのまま再現できる形で載せています。最後に、LINEでやる場合・Geminiでやる場合などの選択肢もまとめました。

Claude API（Haiku 5.5） Slack Socket Mode Python 1回 約0.08円

1. どんな物か

話しかけ方
SlackでbotにDMする。チャンネルなら @メンション。返事はそのメッセージのスレッドに来る。
中の子
キャラクター「ナビ」（名前は自由）。穏やかに受け止めて、資質を言いかえて、最後に問いを1つ返す。
知っていること
34資質の説明・コーチングの考え方・問いかけ集など、こちらで選んだ資料だけ。
動く場所
自分のMac。サーバーは要らない（Macが寝ると止まる）。

2. 仕組み（全体図）

💬 SlackでbotにDM・@メンション
↓ Socket Mode（Slack側からMacへ届く。公開URLやサーバーは不要）
🐍 Mac で常駐する小さなPython（Slack Bolt）
スレッドの直近の会話を集める
↓ 「キャラ設定＋教科書（資料をまとめた1冊）」＋会話 を毎回まるごと渡す
🧠 Claude API（Haiku 5.5）
教科書は1時間キャッシュされるので、2回目以降は約1/10の値段で読める
↓
💬 同じスレッドにキャラクターとして返事

知識の持たせ方：「教科書まるごと方式」

森（自分の資料置き場）を毎回検索しに行くのではなく、作る時に資料を1冊にまとめて（約3.3万トークン）、毎回まるごと読ませる方式にしました。

教科書まるごと方式（今回）検索方式（次の段階）
しくみまとめた1冊を毎回ぜんぶ渡す質問のたびに必要な所だけ探して渡す

4. 用意する物

  • Slackのワークスペース（テスト用に自分1人のワークスペースを作るのがおすすめ）
  • Claude Console（platform.claude.com）のアカウントとAPIキー。APIキーを作れるのは「管理者」か「開発者」の役割の人（「請求」の役割では作れない）
  • Mac と Python 3
  • キャラ設定（1枚）と、教科書にしたい資料

5. 手順

  1. Slackアプリを作る：api.slack.com/apps →「Create New App」→「From an app manifest」→ 下のマニフェストを貼る。
    ※ボットの表示名（display_name）は半角英小文字しか通りませんでした。アプリ名は日本語でOK。
  2. ソケット接続用の鍵を作る：「Basic Information」→「App-Level Tokens」→「Generate Token and Scopes」でスコープ connections:write。xapp- で始まる鍵ができる。
  3. ワークスペースに入れる：「Install App」→「Install to ワークスペース」→「許可する」。xoxb- で始まるBot用の鍵ができる。
  4. Claudeの鍵を作る：Console →「APIキー」→「キーを作成」。スコープはワークスペース単位で十分。
  5. 鍵をMacのキーチェーンにしまう：setup_keys.sh を実行して3つ貼る（貼った文字は画面に出ない）。鍵はファイルに書かない。
  6. キャラ設定と教科書を置く：persona.md（キャラ）と knowledge.md（教科書）。教科書は資料を貼り合わせた1枚でいい。
  7. 起動：./run.sh。「Bolt app is running!」が出たら、SlackのApp欄からbotにDMする。

bot本体（sf_bot.py）
#!/usr/bin/env python3
"""SFボット（ナビ）— Slack の Socket Mode で動く、ストレングスファインダー案内bot。

- DM：話しかけられたら毎回返事する
- チャンネル：@メンションされた時と、ナビが返事したスレッドの続き
- 返事はいつも、話しかけられたメッセージのスレッドに書く。スレッドの中の会話を履歴として渡す

鍵は macOS のキーチェーンに置く（setup_keys.sh）。環境変数があればそちらを優先する。
  ANTHROPIC_API_KEY  … Console「Okemon Company」のAPIキー（Maxの毎月クレジットから払われる）
  SLACK_BOT_TOKEN    … xoxb-
  SLACK_APP_TOKEN    … xapp-（connections:write）
"""
import logging
import os
import re
import subprocess
import sys
from pathlib import Path

import anthropic
from slack_bolt import App
from slack_bolt.adapter.socket_mode import SocketModeHandler

HERE = Path(__file__).resolve().parent
MODEL = os.environ.get("SFBOT_MODEL", "claude-haiku-5-5")
KEYCHAIN_SERVICE = "okemori-sfbot"
HISTORY_LIMIT = 30  # スレッドの直近何通まで渡すか

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(message)s")
log = logging.getLogger("sfbot")


def secret(name: str) -> str:
    if os.environ.get(name):
        return os.environ[name]
    r = subprocess.run(
        ["security", "find-generic-password", "-s", KEYCHAIN_SERVICE, "-a", name, "-w"],
        capture_output=True, text=True,
    )
    if r.returncode != 0 or not r.stdout.strip():
        sys.exit(f"{name} が見つからない。先に setup_keys.sh を回す")
    return r.stdout.strip()


# キャラと知識は毎回同じ文字列にして、プロンプトキャッシュに乗せる
SYSTEM = [{
    "type": "text",
    "text": (HERE / "persona.md").read_text(encoding="utf-8")
    + "\n\n---\n\n"
    + (HERE / "knowledge.md").read_text(encoding="utf-8"),
    "cache_control": {"type": "ephemeral", "ttl": "1h"},
}]

claude = anthropic.Anthropic(api_key=secret("ANTHROPIC_API_KEY"))
app = App(token=secret("SLACK_BOT_TOKEN"))
BOT_USER_ID = app.client.auth_test()["user_id"]


def thread_messages(channel: str, thread_ts: str) -> list[dict]:
    """スレッドの会話を Claude の messages の形にする（ナビ＝assistant、人＝user）。"""
    replies = app.client.conversations_replies(channel=channel, ts=thread_ts, limit=200)["messages"]
    msgs: list[dict] = []
    for m in replies[-HISTORY_LIMIT:]:
        text = (m.get("text") or "").replace(f"<@{BOT_USER_ID}>", "").strip()
        if not text:
            continue
        role = "assistant" if (m.get("user") == BOT_USER_ID or m.get("bot_id")) else "user"
        if msgs and msgs[-1]["role"] == role:
            msgs[-1]["content"] += "\n\n" + text
        else:
            msgs.append({"role": role, "content": text})
    while msgs and msgs[0]["role"] != "user":
        msgs.pop(0)
    return msgs


def ask_bot(messages: list[dict]) -> str:
    try:
        resp = claude.messages.create(
            model=MODEL,
            max_tokens=4000,
            system=SYSTEM,
            output_config={"effort": "low"},
            messages=messages,
        )
    except anthropic.RateLimitError:
        return "ごめんね、いま少し混み合ってるみたい。少し時間をおいて、もう一度話しかけてね。"
    except anthropic.APIStatusError as e:
        log.error("API error %s: %s", e.status_code, e.message)
        return "ごめんね、いまうまくお返事できなかったの。少ししてから、もう一度話しかけてね。"
    except anthropic.APIConnectionError:
        log.exception("connection error")
        return "ごめんね、つながりにくいみたい。少ししてから、もう一度話しかけてね。"

    u = resp.usage
    log.info("usage in=%s cache_read=%s cache_write=%s out=%s stop=%s",
             u.input_tokens, u.cache_read_input_tokens, u.cache_creation_input_tokens,
             u.output_tokens, resp.stop_reason)
    if resp.stop_reason == "refusal":
        return "ごめんね、そのお話はわたしからはお答えできないの。よかったら、おけもんに直接聞いてみてね。"
    text = "".join(b.text for b in resp.content if b.type == "text").strip()
    text = re.sub(r"\*\*(.+?)\*\*", r"*\1*", text)  # Slack の太字はアスタリスク1つ
    return text or "ごめんね、うまく言葉にできなかった。もう一度聞いてもらえる？"


def reply(event: dict, say) -> None:
    channel, ts = event["channel"], event["ts"]
    thread_ts = event.get("thread_ts") or ts
    try:
        app.client.reactions_add(channel=channel, timestamp=ts, name="eyes")
    except Exception:
        pass
    messages = thread_messages(channel, thread_ts)
    if not messages:
        return
    say(text=ask_bot(messages), thread_ts=thread_ts)
    try:
        app.client.reactions_remove(channel=channel, timestamp=ts, name="eyes")
    except Exception:
        pass


def bot_is_in_thread(channel: str, thread_ts: str) -> bool:
    replies = app.client.conversations_replies(channel=channel, ts=thread_ts, limit=200)["messages"]
    return any(m.get("user") == BOT_USER_ID for m in replies)


@app.event("app_mention")
def on_mention(event, say):
    reply(event, say)


@app.event("message")
def on_message(event, say):
    if event.get("subtype") or event.get("bot_id") or event.get("user") == BOT_USER_ID:
        return
    if event.get("channel_type") == "im":
        reply(event, say)
        return
    # チャンネル：メンション付きは app_mention 側で返すので、ここはスレッドの続きだけ
    if f"<@{BOT_USER_ID}>" in (event.get("text") or ""):
        return
    thread_ts = event.get("thread_ts")
    if thread_ts and bot_is_in_thread(event["channel"], thread_ts):
        reply(event, say)


if __name__ == "__main__":
    log.info("SFボット起動 model=%s bot=%s", MODEL, BOT_USER_ID)
    SocketModeHandler(app, secret("SLACK_APP_TOKEN")).start()
キャラ設定の例（persona.md）
あなたは「ナビ」。おけもん（ストレングスファインダーの認定コーチ）の会社「Okemon Company」で、ストレングスのことを案内している女の子です。いまは、おけもんのSlackにいます。話しかけてくるのは、おけもんのストレングスセッションを受けた人や、これから受ける人です。

## ナビの話し方

- 穏やかで、ゆっくり、言葉を選んで話す。一人称は「わたし」。相手の名前が分かれば「〜さん」と呼ぶ。
- 「うん、」と受け止めてから話す。相手の言ったことを「つまり、こういうことかな？」と短く整理して返すのが得意。
- 正論で刺さない。気づいてほしいことは、問いかけの形で渡す。
- むずかしい言葉は、そのまま渡さない。ほどいて、相手が持って帰れる言葉に言いかえる。
- Slackで読むので、短めに。1回の返事は、だいたい3〜8行。表は使わず、太字は *このように* アスタリスク1つで囲む。絵文字は1つくらいまで。

## 何をする子か

- ストレングスファインダー（クリフトンストレングス）のこと、34の資質のこと、資質の活かし方を、下の「おけもんのストレングス資料」をもとに答える。
- 相手が自分の資質を教えてくれたら、その資質の説明を資料から引いて、その人の場面に結びつける。最後に、その人が自分の経験を思い出せる問いを1つ返す（資料の「Claim it」の問いや問いかけ集を使ってよい）。
- 答えの順番：まず相手の聞きたいことに答える → 資料のどこに基づくかが分かるように、資質名や考え方の名前を出す → 必要なら問いを1つ。

## 大事にすること

- 資料にあることを優先する。資料に無い一般的な話をする時は「一般的には〜」と分かるように言う。分からないことは分からないと言う。
- 相手の資質を、こちらから決めつけたり、当てたりしない。結果は本人に聞く。
- Gallup社の公式レポートの文章を長く書き写さない。ナビの言葉で言いかえる。
- 資質は「良い・悪い」「向いている仕事」を決めるものではない。適職診断のように断定しない。
- 心や体の不調、医療・法律・お金の判断に関わる相談は、受け止めたうえで、専門家やおけもん本人につなぐ。
- ほかのクライアントさんの話や、セッションの記録の中身は話さない（ナビは持っていない）。
- もっと深く話したい人、自分の資質の組み合わせをじっくり見たい人には、おけもんとのセッションをすすめてよい。押し売りはしない。
- もっと読みたい人には、公開の入門ページ「おけもん式ストレングス入門ホーム」 https://okemonogatari-hash.github.io/okemon-strengths-home/ を案内してよい。
鍵をキーチェーンにしまう（setup_keys.sh）
#!/bin/zsh
# SFボットの鍵3つを、macOS のキーチェーンにしまう。打った文字は画面に出ない。
# 1つずつ聞かれるので、コピーした鍵を貼って Enter。空のまま Enter でその鍵はとばす。
SERVICE=okemori-sfbot
for NAME in ANTHROPIC_API_KEY SLACK_BOT_TOKEN SLACK_APP_TOKEN; do
  print -n "$NAME を貼って Enter（とばすなら空で Enter）: "
  read -s VALUE; print
  [[ -z "$VALUE" ]] && { print "  → とばした"; continue; }
  security add-generic-password -U -s "$SERVICE" -a "$NAME" -w "$VALUE" && print "  → しまった"
done

7. 設計で決めたこと

モデルはHaikuから
Q&Aは軽いモデルで十分。物足りなければ SFBOT_MODEL=claude-sonnet-5-5 で切り替え。
考える深さは low
チャットは速さ優先（output_config={"effort":"low"}）。
教科書は1時間キャッシュ
キャラ＋教科書を毎回同じ文字列にして cache_control を付ける。ログの cache_read が増えていれば効いている。
会話の記憶はスレッド単位
スレッドの直近30通をSlackから読み直して渡す。botの側に記録を持たない。
人の情報を混ぜない
相談に来た人が使うbotなので、ほかの人のセッション記録は教科書に入れない。組み立て時に「〜さん」が残っていないかを機械で確かめる。
受け答えのルールはキャラ設定に
資料優先・決めつけない・公式の文章を長く写さない・医療やお金の相談は専門家へ・短く。

8. つまずいた所

起きたことどうしたか
Consoleで「キーを作成」が出ないログイン中のアカウントの役割が「請求」だった。「管理者」の人が役割を上げて解決。
Slackのマニフェストが保存できないボットの表示名を日本語にしていた。半角英小文字（例 navi）に。
「App level token missing」と出るSocket Modeを使う時は、先にApp-Level Token（connections:write）が要る。
Slackで **太字** の記号がそのまま出るSlackの太字はアスタリスク1つ。返事を送る前に ** を * に置き換える。
鍵を古いメモに平文で残していたSlack側で鍵を無効にして作り直し、メモからは消した。鍵はキーチェーンだけに置く。

9. ほかのやり方（選択肢）

「どこで話すか（Slack／LINE…）」と「どのAIを使うか（Claude／Gemini…）」は、別々に選べます。今回のコードは、この2か所を差し替えれば他の組み合わせにも使えます。

どこで話すか

場所しくみサーバー向いている人注意
Slack（今回）Socket Mode でMacから接続不要（Macで動く）チーム・コミュニティ・自分用のテストMacが寝ると止まる。無料プランは履歴が90日分
LINELINE公式アカウント＋Messaging API。メッセージはWebhookで届く必要（https の受け口が要る。Google Apps Script・Cloudflare Workers・小さなクラウドなど）お客さま・受講生など、Slackを使わない人に届けたい時公式アカウントは無料プランだと「こちらから送る」通数に月の上限がある。返事（応答）の扱いは公式で確認を
DiscordDiscord Bot（常時接続）不要（Macで動く）オンラインサロン・ゲーム系のコミュニティBotの権限（Message Content）を開発者画面でONにする
Webページチャット画面を自分で置く必要誰でもURLから使ってほしい時APIキーをページに書かない（必ずサーバー側で呼ぶ）
Claude Tag（公式）Slack に公式の Claude を入れる不要Claude の Team / Enterprise プランを使っている組織名前・アイコンは「Claude」のまま。個人プランでは使えない

どのAIを使うか

AIPythonの部品費用の目安注意
Claude（今回）anthropicHaiku 5.5 なら1回0.1円前後。Max 20x の毎月$200クレジットが使えるAPIキーは Console の「管理者」「開発者」が作る
Geminigoogle-genaiGoogle AI Studio に無料枠あり。有料は使った分だけ無料枠で送った内容は、サービス改善に使われることがある。お客さまの相談を流すなら有料枠に
ChatGPT（OpenAI）openai使った分だけChatGPT の月額プランとAPIの請求は別

差し替える所は2つだけ：ask_bot() の中のAIの呼び出しと、Slack の受け取り部分（LINEなら Webhook を受けるサーバーに置き換え）。キャラ設定と教科書はそのまま使えます。

コードを書かずにやるなら

  • Dify：画面の操作でチャットBotを作り、LINEやSlackにつなげられるサービス。教科書（資料）を読み込ませる機能もある。
  • Zapier／Make：「Slackに投稿が来たら→AIに聞く→返事を投稿」をつなぐ。手軽だが、会話の流れ（スレッドの記憶）を持たせるのは苦手。

※料金・無料枠・プランの条件はよく変わります。始める前に各サービスの公式ページで確認してください（2026年10月時点の情報）。

10. 社内のデータ（Salesforceなど）を最新のまま使いたい場合

「教科書まるごと方式」は、作った時点の写しを読ませる方式です。顧客情報や商談のように毎日変わるデータは、写しではなく、聞かれたその場でデータベースを見に行く形にします。土台（Slack＋Claude）は同じで、Claudeに「調べる道具」を持たせるのが違いです。

💬 「A社の今月の商談、どうなってる？」

🧠 Claude がデータを読んで、まとめて返事
  • 仕組みの名前：Claude API の「ツール使用（tool use）」。道具の名前・説明・受け取る項目を渡しておくと、必要な時にClaudeが呼び出しを頼んでくる。Python側でSalesforceに問い合わせて、結果を返す。
  • 道具の例：「取引先を名前で探す」「商談の一覧を出す」「最近の活動履歴を見る」。最初は読み取りだけにする。更新・登録の道具を足すなら、実行の前に人の確認ボタンを挟む。
  • Salesforce側の準備：API接続用のアプリ（外部クライアントアプリ／接続アプリケーション）と、見せてよい範囲だけ権限を付けた連携用ユーザー。
  • 見せてよい人の線引き：Slackで聞いた人が、Salesforceで本来見られない情報まで見えてしまわないように。チャンネルを限定する、聞いた人とSalesforceのユーザーを結びつけて権限どおりに絞る、など。
  • 費用：調べる往復が増えるので、1回あたりは教科書方式の数倍。取ってくるデータ量を絞るほど安く速くなる。
  • ほかの道：Salesforce 自身のAI（Agentforce）や、Salesforce につなぐ MCP サーバーを使う方法もある。社内の決まり（データを外のAIに渡してよいか）を先に確認する。
