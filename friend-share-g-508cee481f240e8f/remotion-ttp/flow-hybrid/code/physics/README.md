# 一球の接触から倒壊するボウリング素材

Flowの投球・喜びの間へつなぐ、完全3Dの4.5秒素材。最終出力は `physics.mp4`、720×1280、60fps、音声なし。

球は `BALL_SINGLE` の1メッシュ。球の前進と半径に応じた回転はキーフレーム制御、10本のピンは実形状MESHコライダーを使い、Blender Bulletで衝突・重力を計算して、その結果の全フレーム姿勢をベイクする。ピンの倒壊角度や倒壊順を手で指定してはいない。球の運動まで含む完全自由な物理計算ではない。

Flow参照は `../raw/flow-story-v2.mp4`。濃紺マーブルの球、琥珀色の木製レーン、青い王冠パネルを継承。キャラクターのいない接触ショットとして明示的にカットをつなぐ。

## 再作成

```sh
/opt/homebrew/bin/blender -b --python build_shot.py -- --render none
/opt/homebrew/bin/blender -b bowling-baked.blend --python render_eevee.py
/opt/homebrew/bin/blender -b bowling-baked.blend --python verify_geometry.py
./render-final.sh
```

`build_shot.py` が造形・質感・照明・動き・物理計算の正本。`bowling.blend` は計算前、`bowling-baked.blend` は確定した全ピン姿勢、`bowling-eevee-linear.blend` は最終カメラとレンダー設定を含む保存版。`poses.json` は全270フレームの球とピンの位置、ピンの向き。

初期スチルは `stills/`、画角修正後の照明前試作は `stills-v2/`、親が受入した画角照明は `stills-v3/`、最終MESHの確認スチルは `stills-final/`。試行物を完成版と取り違えない。最終検証は `physics-qa.json` と、動画のエンコード後に保存する `video-qa.json`。

## 表現の範囲

実物理は映像中の見た目に合わせた相対寸法と材質係数で計算している。ボウリング場の公式寸法や競技球の計測再現ではない。開始から接触までの時間をTTPの約2.63秒に合わせ、球の分裂・逆行・接触前の先倒れを防ぐ素材として作った。

## 最終接触の計測

球と最初のピンの実メッシュ間距離を、ピンが直立している初期状態に対して二分法で調べた接触時刻は **2.633390秒**（60fpsの159.0034フレーム、フレーム番号は1始まり）。ソルバーが最初にピンを水平移動させるのは159フレーム＝2.633333秒。差は0.000057秒。1〜158フレームの全ピンは位置・傾きとも差0。

衝突解決後に可視表面間の距離を測ると約4mmの分離がある。これは解決後の姿勢であり、そのフレームにメッシュが相互貫通していないことは接触の不存在を示さない。そのため接触前の連続交差時刻と、ソルバーの最初の反応を別々に記録した。球は1個、世界座標yは全270フレームで単調増加。全10本の最終上向きベクトルのz成分は絶対値0.7未満。

凸包試行から最終MESHへ変更。さらに衝突マージン0も試したが7番ピンが残ったため、Blender標準の自動感度を使うMESH条件を最終とした。0マージン試行のblendは `trials/`、過去スチルとチューニングJSONは履歴であり完成証拠には使わない。衝突形状とマージンの性質は [Blender公式マニュアル](https://docs.blender.org/UATEST/manual/en/dev/physics/rigid_body/properties/collisions.html) を参照。

## 球を消した比較計算

ピンを159フレームで固定解除するのは、開始直後の床へのごく小さい落下を見せず、接触までラックを静かに保つため。固定解除そのものを倒壊原因にしていないかを `counterfactual_test.py` で調べた。同じMESH・床・重力・解除時刻のまま球の剛体だけを取り除くと、270フレームまで10本直立・倒壊0本。最大傾き0.0485度、水平ずれ最大0.35mm。球ありでは10本倒れる。結果は `counterfactual-qa.json`。

カメラを進める試作では、中盤にカメラが球を追い越し、球の投影半径が一度大きくなる問題を検出した。固定カメラと、最大速度3.1m/s（球3.3509m/sより遅い）で追いかける案を比較。後者は全159フレームで画面yが単調に上がり、球半径も単調減少。数値は `camera-linear-qa.json`、固定比較は `camera-fixed-qa.json`。

最終採用は親が2種類の実スチルを比較して選んだ低速追従カメラ。`build_shot.py` もこのカメラを既定に更新した。最終PNGは `frames-final/`、MP4は `physics.mp4`。`camera-linear-qa.json` の投影検査はこの最終カメラへ対応する。TTPの時間と接触因果を参照しているが、固定カメラや全投球フォームの完全一致を称する素材ではない。

## 保存後の確認

最終MP4は1.7MB、H.264/yuv420p、720×1280、60fps、270フレーム、4.500秒、音声ストリーム0。全270フレームのデコードが成功。黒画面と0.5秒以上の静止異常は検出なし。MP4から再抽出した158/190/270フレームを作者が読み返し、直立・球の通過後の倒壊・立ったピンが残らない最終状態を確認した。再抽出画像は `qa-rendered/`。全編のキャラクター投球・リアクションとの接続受入は親の最終合成で行う。
